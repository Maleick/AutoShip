# Write Endpoint Unbounded Serde Fields Audit — 2026-04-19

Parent issue: #2290

## Endpoints Audited

This pass covers remaining write endpoints beyond `chat-pattern-rules` and `loot`.

---

### 1. `POST /api/soul/debrief` — `receive_session_debrief`

**File:** `textquest-web/src/api/soul.rs`

**Struct:** `SessionDebrief`

**Risk:** High — caller-supplied strings (`session_id`, `created_at`, `wins[]`, `losses[]`, `suggestions[]`) stored in-memory without length checks. Vec fields have no item count cap.

**Fields guarded:**
| Field | Limit | Type |
|---|---|---|
| `session_id` | 512 bytes | string length |
| `created_at` | 512 bytes | string length |
| `wins` | 50 items | vec item count |
| `wins[i]` | 512 bytes | string length per item |
| `losses` | 50 items | vec item count |
| `losses[i]` | 512 bytes | string length per item |
| `suggestions` | 50 items | vec item count |
| `suggestions[i]` | 512 bytes | string length per item |

**Response on violation:** `422 Unprocessable Entity` with `{"error": "<description>"}`.

**Constants:** `DEBRIEF_FIELD_MAX_LEN = 512`, `DEBRIEF_VEC_MAX_LEN = 50`

---

### 2. `PUT /api/kill-tracker/settings` — `put_settings`

**File:** `textquest-web/src/api/kill_tracker.rs`

**Struct:** `KillTrackerSettings`

**Risk:** Medium — `auto_report_channel` (String) has no length bound; `max_session_history` (usize) has no upper cap and controls in-memory allocation.

**Fields guarded:**
| Field | Limit | Type |
|---|---|---|
| `auto_report_channel` | 64 bytes | string length |
| `max_session_history` | 10,000 | numeric upper bound |

**Response on violation:** `422 Unprocessable Entity` with `{"error": "<description>"}`.

**Constants:** `CHANNEL_MAX_LEN = 64`, `MAX_SESSION_HISTORY_LIMIT = 10_000`

---

## Tests Added

- `soul.rs`: 9 unit tests covering valid pass-through and rejection of oversized strings/vecs for each field.
- `kill_tracker.rs`: 4 unit tests + 2 async integration tests covering valid pass-through, oversized channel, and oversized history limit (including HTTP status checks).

## Not Guarded (out of scope or low risk)

- `theme_config.rs`: already guards via allowlist (`validate()` checks exact string equality — effectively bounded).
- `extensions.rs`: already has `validate_settings` / `validate_setting_value` per-field guards.
- `vendor_watch.rs`: already has `validate_config` called before writes.
- `admin_sessions.rs`: write handlers validate session existence; no unbounded free-text fields.
