## What it is

`textquest` is the **external orchestrator** binary for the TLP multibox system. It runs outside the EQ client process and coordinates up to 36 concurrent clients by:

1. Spawning and authenticating `eqgame.exe` processes (staggered logins).
2. Injecting a stealth DLL (`textquest-dll`) into each client.
3. Reading live game state from remote process memory + DLL-published shared memory.
4. Dispatching slash commands and structured IPC back into each DLL.
5. Running camp/hunt/combat/loot/zoning state machines on top of the live fleet.
6. Exposing a Ratatui TUI dashboard + Discord bot + webhook alerts.

The companion `textquest-dll` crate is injected; the `textquest-soul` workspace crate handles the long-term behavioral memory. This doc covers only the orchestrator binary.

Key cross-cutting contracts:

- **Session tokens.** Written to disk _before_ `LoadLibraryW` so the DLL can authenticate its IPC pipe on init (see `inject::loader`, `ipc::pipe`).
- **Correlation IDs.** `CommandPipe::send` tags every command with a u64 correlation ID; responses are validated or the call bails.
- **Linked-list spawn walk.** `eq::spawn::read_all_spawns` backtracks from `pinstLocalPlayer` to the list head (≤ 4096 steps) then walks forward with cycle detection.
- **Injection verification.** Trust the remote-thread exit code (HMODULE), _not_ PEB module enumeration — the DLL unlinks itself for stealth.
- **Zone transition backoff.** `zoning::ZoneFailureState` maps codes deterministically to recovery actions; retries use `2^(attempts-1)` seconds, capped at 30s.

cargo test  -p textquest             # unit tests (skips Windows-only paths)
cargo run   -p textquest -- --help   # subcommand list

# Windows cross-compile from Mac (see feedback_windows_cross_compile):

  cargo build --target x86_64-pc-windows-gnu --release
