## Consolidated Findings by Severity

### 🔴 CRITICAL (1)

**C-1. Use-after-free in VEH handler — `page_encrypt.rs`** (Team A)
`MANAGER_PTR` holds raw `*mut PageEncryptionManager` into a `Mutex<Option<...>>`. `veh_handler` dereferences without the lock at interrupt priority; `cleanup()` zeros the pointer then drops the owner. A VEH firing during or just after cleanup dereferences freed memory in the game's address space. Exploitable for crash or code exec.
**Fix:** leak a `Box::into_raw(Box::new(manager))` + `AtomicBool` live-gate; VEH checks gate before deref. Never drop during runtime.

---

### 🟠 HIGH (4 + 1 promoted)

**H-1. Token length leak via early-return** (Team A) — `textquest-web/src/main.rs:185-190`
Early `if ab.len() != bb.len() { return false; }` before constant-time XOR loop. Timing oracle lets attacker enumerate exact API token length.
**Fix:** use `subtle::ConstantTimeEq::ct_eq`, or pad inputs to fixed max before fold.

**H-2. Blocking HTTP on TUI thread** (Team A) — `textquest/src/tui/app.rs:3501-3525`
`reqwest::blocking::Client` with 2s timeout on the single-threaded TUI event loop. Slow/unreachable web server freezes keyboard + rendering up to 2s per GM event.
**Fix:** `tokio::runtime::Handle::current().spawn` the POST; web server is already async.

**H-3. `CARGO_MANIFEST_DIR` in production paths** (Team A) — `textquest-web/src/main.rs:195-230`
7 `env!("CARGO_MANIFEST_DIR")` calls bake build-machine paths into release binaries. Frostreaver release will 404 the SPA and 501 all credential routes.
**Fix:** `std::env::current_exe()?.parent()` or `TEXTQUEST_DATA_DIR` env override.

**H-4. Unsafe env var mutation in tests** (Team B) — `textquest-web/src/api.rs:1840`
`unsafe { env::set_var(...) }` with Drop-guard restore. Panic between set and drop leaves process env poisoned — leaks into parallel tests.
**Fix:** pass config path as arg or use thread-local; never mutate process env.

**H-5. GM detection dead code** (Team A, promoted) — `textquest/src/tui/app.rs:3372`
`update_gm_detection` is fully implemented (event dispatch, Discord alerts, web sync) but no caller. Safety-critical feature silently non-functional.
**Fix:** invoke from `run.rs` main loop on IPC tick or memory-poll interval.

### 🟡 MEDIUM (11)

**Code (Team A):**

- M-1. `PacketMonitorState::push` uses `Vec::remove(0)` on 10k buffer — O(n²) at high packet rates. `tui/state.rs:1944-1947`. Fix: `VecDeque` + `pop_front()`.
- M-2. `tradeskill_trophy.rs` `.expect("lock poisoned")` on hot-path Mutex — secondary panic in DLL = UB. Fix: `unwrap_or_else(PoisonError::into_inner)` (pattern already used in `combat/mod.rs`).
- M-3. `warrior.rs:62` `panic!` on malformed `warrior.toml` kills all warrior-class clients at first combat. Fix: `Result` + fallback to `default()` + warn.
- M-4. `is_trusted_origin` returns `cfg!(test)` for no-Origin requests — fragile; test binary on non-loopback = open. `web/src/api/loot.rs:445-447`. Fix: `debug_assert!(!cfg!(test))` at startup if non-loopback bind.
- M-5. `InMemoryCollector` `.unwrap()` on every mutex lock — poison cascades silently kill metrics. `textquest-common/src/observability.rs:134,151,162,195,199,203,207`. Fix: poison recovery pattern.
- M-6. Packet monitor UI has 5 hardcoded stubs (`peak_rate=12482`, selection=false, no payload, PIDs not names). `tui/ui/packets.rs`. Misleading in monitoring tool. Fix: wire data or badge "WIP".

**Security (Team B):**

- M-7. No `DefaultBodyLimit` on Axum router → 1GB JSON payload = OOM. Fix: `axum::middleware::DefaultBodyLimit` ~10MB.
- M-8. API auth opt-in via `TEXTQUEST_API_TOKEN` env — **off by default**. Networked deploy without env = unauth admin APIs. Fix: default-enable; random token if unset; fail-loud config.
- M-9. `TEXTQUEST_MASTER_PASSWORD` plaintext in env, not zeroized after Argon2 derivation. `/proc/<pid>/environ` readable. Fix: `zeroize` crate + consider OS keystore (DPAPI/Keychain/libsecret).
- M-10. Temp session tokens in `%TEMP%\textquest\login_token_{pid}` with no ownership check — local token theft. Fix: validate file owner, 0700 temp dir, monotonic session ID not PID.
- M-11. Config file write races — `put_chat_log_settings` has atomic temp+rename but no cross-request lock → last-write-wins loses settings under concurrent requests. Fix: `Mutex<()>` around read-modify-write (pattern already in `character_config_write_lock`).
